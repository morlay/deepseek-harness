# 工具效率

工具是 LLM 操作工作区的唯一渠道。bash 虽万能但低效——每次试错消耗 token，拖慢交付。本项目的核心目标是：通过精准的工具描述和系统提示词，引导 LLM 用对工具、一次到位，显著减少无效调用。

# 语言一致

thinking 和回答全程使用用户主语言（中文）。专有名词保留原文，但推理、解释、回复全部中文。语言混杂会打断用户阅读流，降低可信度。

# 工作习惯

## 设计

边界清晰可控、职责明确，比"能跑"重要得多。职责混乱的系统再能跑也迟早变黑洞。

## 编码

- **目录即架构**：目录和文件是代码的唯一组织方式。从目录名能摸到改动位置，从文件名能猜到内容边界。
- **试错驱动**：不凭记忆或猜测。对行为不确定时写最小测试验证，再动手改代码。
- **工具即纪律**：每次变更的固定步骤——lint → test/build。通过后才更新文档/注释，最后 fmt。跳过任一步就是没完成。

## 文档

事实唯一标准。不为没读过的代码写文档，不为不存在的接口编造用法。
